# Project 1 — EDA Foundations
### NovaFit Wellness: Understanding Member Churn

**Difficulty:** Beginner
**Estimated time:** 8–14 hours (spread over 3–5 sessions)
**Dataset:** `data/data.csv` — 3,034 rows × 21 columns

---

## What this project is

You are handed a member database from a gym chain and a business problem:
*members are cancelling, and nobody knows which ones are about to.*

Your job in this project is **not** to build a model. It is to understand the
data well enough that a model would be worth building — and to know what would
go wrong if someone built one carelessly.

## How to use this repository

1. Read `EDA_GUIDE.md` **from the top**, at least through Section 6.
2. Work through the phases in order. Each phase is self-contained.
3. Write your code in `notebooks/eda.ipynb` (create it yourself).
4. Record findings using the Observation Framework (Guide § A2) as you go.
5. Produce `reports/EDA_REPORT.md` at the end.
6. Submit for evaluation against the rubric in Guide § 22.

```text
Project_1/
├── data/
│   └── data.csv          <- your dataset (do not edit this file)
├── notebooks/
│   └── eda.ipynb         <- YOU create this

└── README.md             <- this file
```

## The ground rules

| You do | The guide does |
| ------ | -------------- |
| Write every line of code | Tell you what to investigate and why |
| Choose the visualisations | Teach you how to choose |
| Discover the data problems | Tell you which *categories* of problem exist in the wild |
| Interpret the findings | Show you how to reason about findings |
| Make the EDA decisions | Give you hints when you're stuck |

**The guide contains no solution code and no list of this dataset's defects.**
That is deliberate. Finding them is the project.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install pandas numpy matplotlib seaborn jupyter
jupyter notebook
```

Details and the reasoning behind each library: Guide § 5.

## Rule zero

> Never change `data/data.csv`. Clean in memory, in your notebook, with code
> that anyone can re-run. An undocumented manual edit to a raw file is the
> fastest way to make an analysis unreproducible.
